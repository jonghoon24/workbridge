# 도메인 규칙

WorkBridge가 **왜 이렇게 동작하는지**를 도메인별로 적는다. 여기에는 제품 결정과 그 이유, 여러 파일에 걸친 정책,
용어, 상태 전이만 둔다. 수치(요율, 한도, 기한, 시각)는 코드 상수가, 요청·응답 모양과 상태 코드와 오류 메시지는
OpenAPI가 원본이라 여기서는 상수 이름만 가리킨다. 코드 구조(레이어, 요청 흐름, 로깅)는
[ARCHITECTURE.md](../ARCHITECTURE.md), 테이블과 제약은 [DATABASE.md](../DATABASE.md)에 있다.

## 용어

| 화면 용어 | 코드 이름 | 뜻 |
| --- | --- | --- |
| 의뢰인 | `CLIENT` (`Role`) | 프로젝트를 올리고 지원자를 골라 계약하고 마일스톤 대금을 결제하는 사람 |
| 프리랜서 | `FREELANCER` (`Role`) | 프로젝트에 지원하고 계약 후 작업을 제출해 정산을 받는 사람 |
| 프로젝트, 모집 예정·모집 중·모집 마감·진행 중 | `Project`, `UPCOMING`·`OPEN`·`CLOSED`·`IN_PROGRESS` | 의뢰인이 올린 외주 건과 그 모집·진행 상태. 진행 중은 계약이 서명돼 작업이 시작된 상태 |
| 지원 | `Application` | 프리랜서의 지원서. 희망 금액(`expectedRate`)이 계약 금액이 된다 |
| 계약, 서명 대기·계약 진행 중·완료·철회됨 | `Contract`, `PENDING`·`ACTIVE`·`COMPLETED`·`CANCELLED` | 지원을 수락하면 생기는 계약. 양측 서명으로 시작된다. 서명 전에는 당사자가 철회할 수 있다 |
| 마일스톤 | `Milestone` | 계약 금액을 나눈 작업 단위. 결제·제출·승인·정산이 모두 마일스톤 단위다 |
| 안전결제 | `Payment` + 마일스톤 `FUNDED` | 의뢰인이 마일스톤 대금을 먼저 결제하고, 플랫폼이 보관하다가 승인되면 프리랜서에게 정산한다 |
| 결제 대기·작업 중·검수 대기·수정 요청·승인 완료 | 마일스톤 `PENDING`·`FUNDED`·`SUBMITTED`·`REVISION_REQUESTED`·`APPROVED` | 마일스톤 상태 |
| 결과물 제출, 검수 | `MilestoneSubmission` | 프리랜서가 회차(`round`)마다 올리는 결과물과 의뢰인의 판단 |
| 자동 승인 | `approvalType: AUTO` | 검수 기한 안에 판단이 없으면 시스템이 승인한다 |
| 정산 항목 | `SettlementItem` | 승인된 마일스톤 하나의 금액·수수료·부가세·지급액 원장 |
| 정산, 지급 예정·지급 보류·지급 완료·지급 실패 | `Settlement`, `SCHEDULED`·`ON_HOLD`·`PAID`·`FAILED` | 프리랜서 한 명의 한 주 정산 항목 묶음과 그 지급 상태 |
| 지급 계좌 | `PayoutAccount` | 정산금을 받을 프리랜서 본인 명의 계좌 |
| 대화방, 시스템 메시지 | `Conversation`, `Message.kind = SYSTEM` | 계약마다 하나인 당사자 간 대화와 그 안의 이벤트 기록 |
| 알림, 알림 설정 | `Notification`, `NotificationPreference` | 인앱 알림과 사용자별 채널(인앱·이메일) 설정 |
| 수수료 | `PLATFORM_FEE_RATE_BPS` | 승인된 마일스톤 금액에 매기는 플랫폼 수수료. 프리랜서가 부담한다 |

## 공통 정책

### 소프트 삭제

`User`와 `Project`는 행을 지우지 않고 `deletedAt`을 채운다. 삭제된 사용자와 프로젝트는 **어디서도 보이지 않고,
아무것도 할 수 없다.** 모든 조회와 쓰기가 `deletedAt: null`로 거른다.

사용자 삭제는 두 가지다. 회원이 설정 화면에서 직접 하는 **탈퇴**([accounts.md](accounts.md#회원-탈퇴))는 개인정보를 지우거나
알아볼 수 없게 바꾼 뒤 소프트 삭제하고, 운영자가 DB에서 `deletedAt`만 채우는 **운영자 삭제**(이용 제한)는 행을 그대로 둔다.
아래 규칙은 둘 다에 적용되고, 다른 점은 따로 적는다. 프로젝트 삭제는 의뢰인이 `DELETE /api/projects/:id`로 한다.

- 삭제된 사용자는 로그인·토큰 갱신을 할 수 없고 공개 프로필에서 사라진다. 이미 받은 액세스 토큰으로도 쓰기를
  할 수 없다.
- 삭제된 프로젝트는 목록·상세·지원·북마크에서 사라진다. 그 프로젝트의 계약, 마일스톤, 대화방도 함께 사라진다.
- **돈은 예외다.** 이미 결제된 마일스톤은 프로젝트 삭제로 묶이지 않는다. 자동 승인은 삭제와 무관하게 진행하고,
  정산과 지급 계좌는 삭제된 프로젝트와 상관없이 보이고 지급된다. 한 정산이 여러 계약의 항목을 묶고, 완료된 계약의
  프로젝트는 지워질 수 있기 때문이다.
- 삭제된 사용자에게는 알림과 이메일을 보내지 않는다. 상태 변경 자체는 그대로 일어나고 그 사람 몫의 알림만 빠진다.
- 운영자가 삭제한 사용자의 포트폴리오·경력은 남아 있지만 보이지 않는다. 탈퇴는 포트폴리오·경력을 지운다(항목은 원래
  하드 삭제다).
- **조인된 소유자에게도 적용한다.** 의뢰인이 삭제된 프로젝트는 삭제된 프로젝트처럼 공개 목록·상세·추천, 북마크
  목록, 프리랜서의 내 지원 목록에서 빠지고 지원도 받지 않는다(없는 프로젝트처럼 404). 그래서 삭제된 의뢰인에게 지원
  알림이 갈 일도 없다. 프로젝트 행은 그대로 두고 숨기기만 한다. 다만 계약이 된 지원은 아래 "이미 맺은 관계"라서 내 지원
  목록에 남는다(계약 목록과 같다).
- 삭제된 사용자가 받은 리뷰는 공개 리뷰 목록(`GET /api/users/:id/reviews`)에서 빠진다(없는 사용자처럼 빈 목록).
- 삭제된 프리랜서의 지원은 의뢰인의 지원자 목록에서 빠지고 수락할 수 없다(없는 지원처럼 404). 삭제된 사용자와 새
  관계를 맺지 않는다.
- 이미 맺은 관계는 당사자에게 그대로다. 계약 목록과 대화방은 삭제된 상대방을 저장된 이름으로 보여준다. 탈퇴한 사용자는
  이름을 지웠으므로 '탈퇴한 회원'으로 보인다.
- 가입 시 이메일 중복 확인은 삭제된 사용자도 센다. `email`이 DB에서 유일하기 때문이다. 그래서 운영자가 삭제한 계정의
  이메일로는 다시 가입할 수 없고, 같은 이메일의 Google 로그인도 실패한다. 탈퇴는 이메일을 지우므로 같은 이메일로 다시
  가입할 수 있다.

### 원자성

여러 행을 바꾸는 상태 변경은 하나의 트랜잭션이고, 한 단계라도 실패하면 아무것도 남지 않는다. 변경이 **일으키는**
알림, 이메일 발송 기록, 비동기 작업, 시스템 메시지도 같은 트랜잭션에서 쓴다. 롤백된 변경은 알림도 메일도 작업도
남기지 않는다(트랜잭션 아웃박스).

상태 전이는 "기대한 상태일 때만" 쓰는 조건부 쓰기다. 두 요청이 동시에 같은 전이를 시도하면 정확히 하나만 이기고,
진 사용자 요청은 상태 확인에서 실패한 것과 같은 충돌로 끝나며 아무것도 쓰지 않는다. 같은 사용자의 쓰기가 섞이면
안 되는 곳(지급 계좌와 지급 결정 등)은 사용자 행을 먼저 잠근다. 잠그는 곳과 순서는
[DATABASE.md](../DATABASE.md#동시성-잠금과-조건부-쓰기)에 있다.

### 시간대

달력이 들어가는 규칙("오늘", 마감일, 일 단위 제한, 월요일 정산, 수요일 지급, 연-월)은 **KST, 고정 UTC+9**로
계산한다. 일광 절약 시간은 없다. 저장은 UTC다. 호스트 시간대는 쓰지 않는다(CI와 Vercel은 UTC, 개발 PC는 KST라서
기기마다 답이 달라진다). 헬퍼는 `src/lib/time.ts`에 있다.

- 날짜만 받는 값(`YYYY-MM-DD`)은 KST의 그 하루다. 마감일·기한은 그날이 끝날 때까지, 시작일은 그날 0시부터다.
  그래서 오늘 마감인 프로젝트는 오늘 밤까지 모집 중이다.
- 연-월(`YYYY-MM`)은 KST의 그 달이다.
- 반대로 "N일 뒤" 규칙(자동 승인, 계약 완료 후 대화 기간, 지급 재시도)은 달력 날짜가 아니라 정확한 24시간 단위다.

### 프로필 완성

프로젝트 등록과 지원, 프로젝트 추천은 **프로필이 완성된 사용자만** 쓸 수 있다. 상대가 판단할 최소 정보가 있어야
거래를 시작할 수 있다는 뜻이다. 의뢰인은 회사 정보, 프리랜서는 기술·분야·경력·단가가 그 최소 정보이고, 정확한
조건은 `isProfileComplete`(`src/lib/profileCompletion.ts`)에 있다.

화면의 "프로필 완성도" 퍼센트는 이 관문과 별개인 안내용 점수다([accounts.md](accounts.md#프로필-완성도)).

### 오류 응답

오류 메시지는 호출자가 고칠 수 있는 원인만 말하고, 상태 코드와 상관없이 **내부 정보(파일 경로, 소스 발췌, SQL,
파서의 원문)를 드러내지 않는다**. 500은 버그라서 원인을 응답에 싣지 않고 서버의 error 로그(설정돼 있으면 Sentry)에만
남긴다. 설정이 없어 숨겨 둔 경로(토큰 없는 내부 작업 엔드포인트, 운영의 API 문서)는 없는 경로와 똑같이 답해 존재를
드러내지 않는다. 응답 형식과 문장은 OpenAPI 문서에 있다.
