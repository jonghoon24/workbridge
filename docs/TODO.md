# WorkBridge TODO

이 문서는 `docs/PRD.md` 기준으로 현재 구현 상태를 대조해 정리한 작업 목록이다. 목표는 새로운 기능 확장보다 PRD에 명시된 MVP 플로우를 빠짐없이 동작시키는 것이다.

## 현재 상태 요약

- 프론트엔드 빌드: 통과 (`workbridge-client`, `npm run build`)
- Prisma 스키마 검증: 통과 (`workbridge-server`, `npx prisma validate`)
- Git 상태: `main`과 `origin/main` 동일, 미커밋 변경 없음
- 구현 범위: 인증, 프로필, 프로젝트, 지원, 계약, 결제, 리뷰 API, AI 단가 분석 골격 존재
- 주요 리스크: 계약 완료/리뷰/역할 선택/외부 연동 검증이 PRD 요구사항과 맞지 않거나 플로우가 끊겨 있음

## P0 - 핵심 플로우 차단 이슈

### 1. 계약 완료 처리 API 연결 - 완료

- 처리 내용
  - `PATCH /api/contracts/:id` API를 추가했다.
  - 계약 완료 시 `Contract.status`와 `Project.status`를 하나의 트랜잭션으로 `COMPLETED` 처리한다.
  - 완료 조건 검증을 추가했다: 의뢰인 권한, 계약 `ACTIVE`, 결제 `COMPLETED`.
  - 프론트엔드 계약 상세 화면의 완료 처리를 단일 API 호출로 정리했다.
- 기존 문제
  - 프론트엔드 `workbridge-client/src/app/contracts/[id]/page.jsx`는 `PATCH /api/contracts/:id`를 호출한다.
  - 백엔드 `workbridge-server/src/routes/contracts.routes.js`에는 해당 라우트가 없다.
  - 결과적으로 결제 완료 후 "프로젝트 완료 처리" 버튼이 실패한다.
- 완료 기준
  - 의뢰인이 결제 완료된 계약을 완료 처리하면 `Project.status`와 `Contract.status`가 모두 `COMPLETED`가 된다.
  - 완료 처리 이후 리뷰 작성이 가능하다.

### 2. 리뷰 작성 화면/플로우 구현 - 완료

- 처리 내용
  - 계약 상세 화면에 완료된 계약의 리뷰 작성 폼을 추가했다.
  - 의뢰인/프리랜서가 상대방에게만 리뷰를 작성하도록 `revieweeId`를 자동 설정한다.
  - 별점 1-5, 텍스트 리뷰, 역할별 태그 선택 UI를 추가했다.
  - 이미 작성한 리뷰가 있으면 중복 작성 폼을 숨긴다.
  - 계약 조회 응답에 리뷰 작성자/대상 정보를 포함해 계약 상세에서 리뷰 목록을 표시한다.
- 기존 문제
  - 백엔드 `POST /api/reviews`는 존재하지만 프론트엔드에서 리뷰 작성 UI와 호출 흐름이 없다.
  - PRD의 "프로젝트 완료 상태에서만 리뷰 작성", "상호 평가", "1회만 작성" 플로우가 화면상 완성되지 않았다.
- 완료 기준
  - 완료된 계약에서 양측이 각각 1회 리뷰를 작성할 수 있다.
  - 사용자 공개 프로필에서 작성된 리뷰와 평균 평점이 표시된다.

### 3. 결제 성공 후 계약 상세로 복귀하는 흐름 보강 - 완료

- 처리 내용
  - Toss success/fail URL에 `contractId`를 포함하도록 수정했다.
  - 결제 성공 화면에서 해당 계약 상세로 이동하는 링크를 제공한다.
  - 결제 실패 화면에서 해당 계약 결제 페이지로 재시도하는 링크를 제공한다.
  - `PENDING` 결제는 기존 `orderId`를 재사용하고, `FAILED` 결제는 새 `orderId`로 재시도할 수 있게 했다.
- 기존 문제
  - 결제 결과 페이지는 성공/실패만 표시하고, 사용자가 어떤 계약으로 돌아가야 하는지 안내가 약하다.
  - 결제 생성 응답에는 `paymentId`만 있고 결과 페이지 URL에는 계약 ID가 없다.
- 완료 기준
  - 결제 성공 직후 사용자가 해당 계약 상세로 돌아가 완료 처리까지 이어갈 수 있다.

## P1 - PRD 필수 요구사항 불일치

### 4. Google OAuth 최초 로그인 역할 선택 - 완료

- 처리 내용
  - `User.roleSelected` 플래그와 마이그레이션을 기준으로 OAuth 최초 역할 선택 상태를 관리한다.
  - Google OAuth 신규 사용자는 임시 기본 역할과 `roleSelected: false` 상태로 생성된다.
  - `POST /api/auth/select-role` API로 역할 미선택 사용자만 역할을 확정할 수 있게 했다.
  - 역할 선택 후 새 access token을 발급해 역할 기반 API를 즉시 사용할 수 있게 했다.
  - `/auth/select-role` 화면을 추가하고 OAuth 콜백에서 역할 미선택 사용자를 해당 화면으로 이동시킨다.
- 기존 문제
  - PRD는 최초 소셜 로그인 시 역할 선택 페이지로 이동하도록 요구한다.
  - 현재 백엔드는 Google 신규 사용자를 기본 `FREELANCER` 역할로 생성한다.
- 완료 기준
  - Google 신규 로그인 사용자는 의뢰인/프리랜서 역할을 직접 선택한다.
  - 역할 선택 전에는 프로젝트 등록/지원 같은 역할 기반 기능을 사용할 수 없다.

### 5. 프로젝트 마감 상태 자동/수동 처리 - 완료

- 처리 내용
  - 프로젝트 목록/상세 조회 시 마감일이 지난 `OPEN` 프로젝트를 `CLOSED`로 자동 전환한다.
  - 지원 요청 시에도 마감일을 다시 확인해, 지난 프로젝트는 `CLOSED` 처리 후 지원을 거절한다.
  - 의뢰인 프로젝트 상세 화면에 수동 "모집 마감" 버튼을 추가했다.
- 기존 문제
  - PRD는 마감일 초과 시 `CLOSED` 전환을 요구한다.
  - 현재 목록 조회는 `OPEN` 프로젝트만 보여주지만, 마감일 초과 프로젝트를 자동으로 닫는 로직은 없다.
- 완료 기준
  - 마감일이 지난 프로젝트는 더 이상 지원할 수 없다.
  - 상태 표시가 `CLOSED`로 일관되게 보인다.

### 6. 프로젝트 목록 필터/정렬 검증 - 완료

- 처리 내용
  - 서버 목록 API에 `sort`, `page`, `limit`, `minBudget`, `maxBudget` 검증을 추가했다.
  - 예산 범위가 잘못되거나 음수/비숫자 값이 들어오면 400 응답을 반환한다.
  - 기술 스택 필터는 빈 값을 제거한 뒤 적용한다.
  - 프로젝트 목록 필터/정렬/페이지 상태를 URL 쿼리와 동기화하고, 새로고침 시 복원한다.
- 기존 문제
  - 검색, 카테고리, 예산, 기술 스택, 정렬, 페이지네이션 구현은 있으나 PRD 기준 동작 검증이 필요하다.
- 완료 기준
  - 키워드/필터/정렬/페이지 변경 조합이 안정적으로 동작한다.

### 7. 프로젝트 수정 제한 UX 보강 - 완료

- 처리 내용
  - 지원자가 있는 프로젝트 수정 화면에서 예산/마감일 입력을 비활성화했다.
  - 제한 사유 안내 문구를 추가했다.
  - 지원자가 있는 수정 요청에서는 예산/마감일 필드를 payload에서 제외해 서버 제한과 충돌하지 않도록 했다.
- 기존 문제
  - 백엔드는 지원자가 있으면 예산/마감일 변경을 막는다.
  - 프론트엔드 폼은 사용자가 저장하기 전까지 제한 이유를 알기 어렵다.
- 완료 기준
  - 의뢰인이 제한 조건을 화면에서 바로 이해할 수 있다.

### 8. 에스크로/지급 상태 표현 정리 - 완료

- 처리 내용
  - 계약 상세의 결제 현황에 플랫폼 보관금, 플랫폼 수수료 10%, 프리랜서 지급 예정액을 표시한다.
  - 실제 이체는 MVP 범위 밖이며 완료 승인 후 지급 예정 상태로 관리한다는 안내를 추가했다.
- 기존 문제
  - PRD는 에스크로 결제, 납품 확인, 수수료 차감 후 지급 처리를 설명한다.
  - 현재 모델에는 실제 지급 상태나 수수료 계산 상태가 없다.
- 완료 기준
  - PRD의 결제/지급 흐름이 데모에서 설명 가능한 수준으로 화면에 드러난다.
