# 시드 데이터

```bash
cd workbridge-server
npm run db:seed
# 또는
npx prisma db seed
```

시드는 `workbridge-server/.env`를 dotenv로 읽는다(셸에 이미 있는 변수가 우선한다). `DATABASE_URL`·`DIRECT_URL`과 지급 계좌번호를 암호화할 `PAYOUT_ACCOUNT_ENCRYPTION_KEY`가 필요하다(`workbridge-server/.env.example`). 키가 없으면 아무것도 지우기 전에 멈춘다. 시드는 모든 테이블을 비우고 다시 만든다(이미 시드한 DB에 몇 번을 돌려도 같은 결과). **모든 계정의 비밀번호는 `password123`입니다.**

## 날짜 기준

모든 날짜는 **시드를 돌린 시각**을 기준으로 계산한다. 그래서 언제 다시 시드해도 모집 중 프로젝트의 마감일은 미래이고, 정산 주차는 실제 달력과 맞는다.

- 정산 주차는 월요일 00:00 ~ 다음 월요일 00:00(KST)이다. 아래 표의 "N주 전"은 **배치가 이미 돈 가장 최근 주차**를 1주 전으로 센다. 그 뒤(이번 주)에 승인된 금액은 아직 정산되지 않은 상태다.
- 한도윤의 "지급 예정" 정산은 원래 그 주의 수요일 10:00 지급이다. 시드 시각이 이미 그 수요일 10:00을 지났으면 지급됐어야 하므로, 화면에서 지급 예정 상태가 보이도록 **시드 시각 이후 첫 수요일 10:00**으로 잡는다.
- 정산 금액은 시드가 `src/lib/money.ts`와 같은 공식으로 계산해 넣는다.

## 포트폴리오와 경력

- 프리랜서 모두 포트폴리오(스킬 태그, 대부분 이미지)와 경력(재직 중 1개 이상)이 있다. 이미지는 `placehold.co` 자리표시 이미지라 저장소 버킷 없이 보인다.
- 추천 점수가 사람마다 갈리도록 스킬·카테고리를 다르게 두었다. 예: 박지윤의 추천 프로젝트는 15번 → 13번 → 5번 → 14번 순이다(시드 직후 기준. 최신성 점수가 있어 날이 지나면 점수가 바뀐다).

## 알림, 알림 설정, 이메일

- **알림**: 계정마다 대표 이벤트의 알림이 있고 일부는 읽지 않은 상태다(이벤트마다 빠짐없이 만든 것은 아니다).
- **알림 설정**(기본값과 다른 것만 저장): 박지윤은 "마일스톤 결제" 메일 끔, "정산 예정" 메일 켬. 이수현은 "새 지원자" 메일과 "읽지 않은 메시지" 메일 끔.
- **이메일 발송 기록**: 발송 완료(수정 요청, 계약 완료, 지급 실패, 읽지 않은 메시지 요약)와 실패 1건(정하은의 정산 보류 메일 — `MAIL_PROVIDER`가 잠시 지원하지 않는 값이었던 상황). API로는 보이지 않고 DB(`EmailDelivery`)에서만 본다.

## 작업 큐

반복 작업(지연 스윕, 정리, 주간 정산 배치)은 시드하지 않는다. 서버의 개발 워커나 `npm run jobs:run`이 시작할 때 만든다. 시드 상태가 만들었을 이벤트 작업만 `PENDING`으로 넣고, 실행 시각은 모두 미래다.

| 작업 | 대상 | 실행 시각 |
| --- | --- | --- |
| `milestone.autoApprove` | 계약 B #2 (2차) | 2차 제출 7일 뒤 |
| `milestone.autoApproveReminder` | 계약 B #2 (2차) | 자동 승인 48시간 전 |
| `milestone.dueSoon`, `milestone.overdue` | 계약 B #2, D #2, E #2 | 기한 24시간 전, 기한 |
| `settlement.payout` | 한도윤의 지급 예정 정산 | 지급 예정 시각 |

## 기타

- **지원**: 모집 중 프로젝트의 대기 지원, 거절된 지원, 계약마다 수락된 지원 1건(위 프로젝트 표의 비고)
- **리뷰**: 계약 A, F에서 의뢰인↔프리랜서 상호 평가
- **북마크**: 박지윤(13, 15번), 윤서아(14번), 송민재(13번)

## 둘러보기 시나리오

1. **검수와 결제 (의뢰인)** — `choi@example.com`으로 로그인 → 헤더의 메시지 배지(2) → `/messages`에서 계약 B 대화 확인 → `/my/contracts` → 계약 B → 마일스톤 2 "관리자 기능 개발"(`/contracts/<id>/milestones/<id>`)에서 1차 수정 요청 사항과 2차 결과물 확인 → 승인. 정산 항목이 생기고 박지윤에게 알림이 간다. 이어서 마일스톤 3 "배포·QA"를 결제하면 박지윤이 마지막 단계를 시작할 수 있다. 결제 방법은 환경마다 다르다.
   - 로컬에서 결제 우회를 켰으면(README "로컬 실행") 결제 화면의 **개발용 결제 완료 처리** 버튼으로 바로 끝난다.
