# 시드 데이터

```bash
cd workbridge-server
npm run db:seed
# 또는
npx prisma db seed
```

두 명령은 Prisma가 `.env`를 읽어 준다. `node prisma/seed.js`로 직접 돌리면 dotenv를 읽지 않으므로 `DATABASE_URL`과 `DIRECT_URL`을 셸에 먼저 export한다. 시드는 모든 테이블을 비우고 다시 만든다(이미 시드한 DB에 몇 번을 돌려도 같은 결과). **모든 계정의 비밀번호는 `password123`입니다.**

## 날짜 기준

모든 날짜는 **시드를 돌린 시각**을 기준으로 계산한다. 그래서 언제 다시 시드해도 모집 중 프로젝트의 마감일은 미래이고, 정산 주차는 실제 달력과 맞는다.

- 정산 주차(BEHAVIOR.md M19)는 월요일 00:00 ~ 다음 월요일 00:00(KST)이다. 아래 표의 "N주 전"은 **배치가 이미 돈 가장 최근 주차**를 1주 전으로 센다. 그 뒤(이번 주)에 승인된 금액은 아직 정산되지 않은 상태다.
- 한도윤의 "지급 예정" 정산은 원래 그 주의 수요일 10:00 지급이다. 시드 시각이 이미 그 수요일 10:00을 지났으면 지급됐어야 하므로, 화면에서 지급 예정 상태가 보이도록 **시드 시각 이후 첫 수요일 10:00**으로 잡는다.
- 금액 계산은 `src/lib/money.ts`와 같다(수수료 10%, 수수료의 부가세 10%, 원 단위 절사). 시드가 같은 공식으로 계산해 넣는다.

## 포트폴리오와 경력

- 프리랜서 5명 모두 포트폴리오 2~4개(스킬 태그, 대부분 이미지)와 경력 1~3개(재직 중 1개 이상)가 있다. 이미지는 `placehold.co` 자리표시 이미지라 저장소 버킷 없이 보인다.
- 추천 점수가 사람마다 갈리도록 스킬·카테고리·경력·리뷰를 다르게 두었다. 예: 김서준의 15번 프로젝트 추천 프리랜서는 박지윤 95 → 한도윤 52 → 송민재 30 → 정하은 28, 박지윤의 추천 프로젝트는 15번 98 → 13번 49 → 5번 41.83 → 14번 38.67(시드 직후 기준, 최신성 점수 때문에 날이 지나면 조금씩 바뀐다).

## 작업 큐

반복 작업(지연 스윕, 정리, 주간 정산 배치)은 시드하지 않는다. 서버의 개발 워커나 `npm run jobs:run`이 시작할 때 만든다. 시드 상태가 만들었을 이벤트 작업만 `PENDING`으로 넣고, 실행 시각은 모두 미래다.

| 작업 | 대상 | 실행 시각 |
| --- | --- | --- |
| `milestone.autoApprove` | 계약 B #2 (2차) | 2차 제출 7일 뒤 |
| `milestone.autoApproveReminder` | 계약 B #2 (2차) | 자동 승인 48시간 전 |
| `milestone.dueSoon`, `milestone.overdue` | 계약 B #2, D #2, E #2 | 기한 24시간 전, 기한 |
| `settlement.payout` | 한도윤의 지급 예정 정산 | 지급 예정 시각 |
