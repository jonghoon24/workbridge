## 1. 프로젝트 개요

### 1.1 서비스 소개

**WorkBridge**는 의뢰인과 프리랜서를 연결하는 중개 플랫폼입니다. 의뢰인은 프로젝트를 등록하고 적합한 프리랜서를 찾을 수 있으며, 프리랜서는 자신의 경력과 포트폴리오를 등록하고 원하는 프로젝트에 지원할 수 있습니다. 플랫폼은 프로젝트 탐색부터 계약 체결, 대금 결제까지 전체 외주 프로세스를 안전하게 관리합니다.

### 1.2 학습 목표

- 실제 비즈니스 요구사항을 분석하여 MVP 범위를 설정하고 데이터베이스 스키마를 설계할 수 있다.
- React와 Express를 사용하여 풀스택 웹 애플리케이션을 구현할 수 있다.
- OAuth, PG 결제, OpenAI API 등 외부 Open API를 연동할 수 있다.
- 칸반 보드와 스프린트 계획을 통해 애자일 개발 프로세스를 경험한다.
- 완성된 서비스를 Vercel/Render에 배포하고 운영할 수 있다.

### 1.3 최종 산출물

| 산출물 유형 | 항목 | 설명 |
|------------|------|------|
| 개발 산출물 | 웹 애플리케이션 | 완전히 동작하는 배포된 서비스 URL |
| 개발 산출물 | ERD | 데이터베이스 설계 다이어그램 |
| 개발 산출물 | API 명세서 | 모든 엔드포인트 정의 문서 |
| 프로젝트 관리 | 스프린트 계획서 | 각 스프린트 목표 및 작업 목록 |
| 프로젝트 관리 | 칸반 보드 | GitHub Projects 또는 Notion |
| 프로젝트 관리 | 스프린트 회고록 | 2회 이상의 스프린트 회고 기록 |
| 발표 자료 | 발표 슬라이드 | 프로젝트 소개 및 주요 기능 시연 |

## 3. 과업 #1 — MVP 범위 설정 및 개발 준비

본 과업은 특강 형식으로 2시간 진행됩니다. 강사가 기획 문서와 와이어프레임을 함께 분석하고, 이후 수강생이 개발 환경을 직접 설정합니다.

### 3.1 기획 문서 분석

- 제공된 와이어프레임 PDF를 참고하여 각 화면의 역할과 기능 흐름을 파악한다.
- 기본 기능 / 고급 기능으로 MVP 우선순위를 정리한다.
- 비즈니스 도메인(외주 플랫폼)의 핵심 엔티티를 도출한다: `User`, `Project`, `Application`, `Contract`, `Payment`, `Review`

### 3.2 데이터베이스 스키마 설계

- ERD를 작성하고 팀원과 리뷰한다.
- Prisma schema 파일을 작성하여 ERD를 코드로 표현한다.
- 주요 테이블: `User`, `Project`, `Application`, `Contract`, `Payment`, `Review`

> ✅ **제출:** ERD 이미지 파일 (dbdiagram.io 또는 draw.io 사용 권장)

### 3.3 개발 환경 설정

#### 디렉토리 구조

| 프론트엔드 (React) | 백엔드 (Express) |
|-------------------|-----------------|
| `workbridge-client/` | `workbridge-server/` |
| `  src/` | `  src/` |
| `    components/` | `    routes/` |
| `    pages/` | `    controllers/` |
| `    hooks/` | `    middlewares/` |
| `    services/ (API 호출)` | `    prisma/` |
| `    store/ (상태 관리)` | |

- GitHub 리포지토리 생성 및 초기 커밋
- 환경 변수 파일(`.env`) 설정: `DATABASE_URL`, `JWT_SECRET`, `OPENAI_API_KEY` 등
- Prisma 마이그레이션 실행 및 데이터베이스 초기화

## 4. 과업 #2 — MVP 개발: 기본 기능

과업 #2는 서비스의 핵심 골격이 되는 기본 기능을 구현합니다. 스프린트 1(1~5일차)과 스프린트 2(6~10일차)로 나눠 진행하며, 각 스프린트 종료 시 데모를 진행합니다.

### 4.1 사용자 관리 시스템

#### 4.1.1 회원가입 및 로그인 (이메일)

| 구분 | 기능 설명 | 기술 요소 |
|------|----------|----------|
| 회원가입 | 이름, 이메일, 비밀번호, 역할 선택(의뢰인/프리랜서)으로 가입 | bcrypt 해싱, 이메일 중복 확인 |
| 로그인 | 이메일/비밀번호 검증 후 JWT 발급 | JWT (Access Token + Refresh Token) |
| 로그아웃 | 클라이언트 토큰 삭제 | 로컬스토리지 또는 쿠키 제거 |
| 토큰 갱신 | Access Token 만료 시 Refresh Token으로 재발급 | 토큰 만료 인터셉터 |

#### 4.1.2 소셜 로그인 (OAuth 2.0)

- Google OAuth 또는 GitHub OAuth 중 1개 이상 구현
- 소셜 로그인 시 기존 이메일 계정과 연동 처리
- 최초 소셜 로그인 시 역할 선택 페이지로 이동

> 💡 Passport.js 또는 직접 OAuth 플로우 구현 모두 허용됩니다.

#### 4.1.3 사용자 역할 및 프로필 관리

| 역할 | 프로필 필드 | 특이사항 |
|------|-----------|----------|
| 공통 | 이름, 이메일, 프로필 이미지, 자기소개 | 이미지 업로드 (Multer + 클라우드 스토리지) |
| 의뢰인 (Client) | 회사명, 사업 분야, 웹사이트 | 프로젝트 등록 권한 |
| 프리랜서 | 기술 스택, 경력(년수), 시간당 단가, 포트폴리오 URL | 프로젝트 지원 권한 |

### 4.2 프로젝트 관리 시스템

#### 4.2.1 프로젝트 CRUD

| 기능 | 설명 | 접근 권한 |
|------|------|----------|
| 프로젝트 등록 | 제목, 설명, 카테고리, 예산, 마감일, 필요 기술 스택 입력 | 의뢰인만 가능 |
| 프로젝트 수정 | 등록된 정보 수정 (지원자 있을 경우 예산/마감일 변경 제한) | 의뢰인 (본인 프로젝트만) |
| 프로젝트 삭제 | 소프트 딜리트 처리 (물리 삭제 금지) | 의뢰인 (본인 프로젝트만) |
| 프로젝트 상세 조회 | 프로젝트 정보 + 지원자 수 + 상태 표시 | 모든 사용자 |

#### 4.2.2 프로젝트 목록 및 검색

- **키워드 검색:** 제목, 설명 텍스트 검색
- **필터링:** 카테고리, 예산 범위, 필요 기술 스택, 마감일
- **정렬:** 최신순, 마감임박순, 예산 높은순
- **페이지네이션:** 페이지당 10개, 무한 스크롤 또는 번호형 페이지네이션

#### 4.2.3 프로젝트 상태 관리

| 상태 | 설명 | 전환 조건 |
|------|------|----------|
| 모집중 (`OPEN`) | 프리랜서 지원 가능한 상태 | 프로젝트 등록 시 기본값 |
| 진행중 (`IN_PROGRESS`) | 프리랜서 선정 완료, 계약 체결된 상태 | 의뢰인이 지원자 수락 후 |
| 완료 (`COMPLETED`) | 프로젝트 납품 및 최종 대금 지급 완료 | 양측 완료 확인 후 |
| 취소 (`CANCELLED`) | 프로젝트 취소 처리 | 진행중 이전 단계에서만 가능 |
| 마감 (`CLOSED`) | 마감일 초과 또는 모집 마감 처리 | 자동(마감일 초과) 또는 수동 |

#### 4.2.4 지원 및 지원자 관리

- **프리랜서:** 프로젝트에 지원서(cover letter, 예상 단가, 예상 기간) 제출
- **의뢰인:** 지원자 목록 조회, 지원서 내용 확인
- **의뢰인:** 지원자 수락/거절 처리
- **프리랜서:** 본인 지원 현황 조회 (상태: 검토중 / 수락 / 거절)
- 동일 프로젝트 중복 지원 방지

> ✅ **스프린트 2 종료 기준:** 회원가입부터 프로젝트 지원까지의 전체 플로우가 동작해야 합니다.

## 5. 과업 #3 — MVP 개발: 고급 기능

과업 #3에서는 서비스의 차별화 요소인 AI 분석 기능, 결제 시스템, 리뷰 기능을 구현합니다. 스프린트 3(1~5일차)과 스프린트 4(6~10일차)로 나눠 진행합니다.

### 5.1 프로젝트 단가 분석 시스템 (OpenAI API)

의뢰인이 작성한 프로젝트 제안서를 OpenAI API로 분석하여, 단위 기능별 예상 단가와 전체 예상 단가를 산정합니다.

#### 5.1.1 분석 기능 요구사항

1. 의뢰인이 '단가 분석 요청' 버튼 클릭
2. 프로젝트 설명을 OpenAI API에 전달
3. AI가 단위 기능 목록을 도출
4. 각 단위 기능별 예상 단가(원) 및 근거 산정
5. 전체 프로젝트 예상 단가 합산 결과 반환
6. 분석 결과를 데이터베이스에 저장하고 리포트 형태로 표시

#### 5.1.2 분석 결과 리포트 항목

- 도출된 단위 기능 목록 (기능명, 설명)
- 단위 기능별 예상 단가 및 산정 근거
- 전체 프로젝트 예상 총 단가
- 유사 프로젝트 참고 정보 (AI가 제공하는 레퍼런스)

> 💡 OpenAI Chat Completions API를 사용하고, 응답을 JSON 형식으로 파싱하여 구조화된 리포트를 생성합니다. **프롬프트 엔지니어링이 핵심입니다.**

### 5.2 계약 및 결제 시스템

#### 5.2.1 계약서 생성 및 관리

| 기능 | 설명 |
|------|------|
| 계약서 자동 생성 | 의뢰인이 지원자 수락 시 계약서 초안 자동 생성 (프로젝트명, 금액, 기간, 양 당사자 정보) |
| 계약서 확인 | 양측이 계약서 내용 검토 |
| 계약 체결 | 양측 전자 서명 (체크박스 동의 방식 허용) |
| 계약서 조회 | 체결된 계약서를 언제든지 조회 가능 |

#### 5.2.2 PG 결제 연동 (토스페이먼츠)

- 토스페이먼츠 테스트 환경(sandbox)을 사용하여 결제 기능 구현
- 결제 흐름: 의뢰인 결제 요청 → 토스페이먼츠 결제창 → 성공/실패 콜백 처리 → 결제 검증 API 호출
- 결제 상태 관리: `대기중` / `결제완료` / `환불` / `실패`
- 결제 내역 조회 페이지 구현

> ⚠️ **주의:** 실제 결제가 이루어지지 않도록 반드시 테스트 환경(sandbox)을 사용해야 합니다. 테스트 클라이언트 키를 코드에 직접 노출하지 않고 환경 변수로 관리합니다.

#### 5.2.3 대금 보관 및 지급 관리

| 단계 | 설명 | 처리 주체 |
|------|------|----------|
| 1. 에스크로 결제 | 계약 체결 후 의뢰인이 전체 금액을 플랫폼에 선결제 | 의뢰인 |
| 2. 작업 진행 | 프리랜서가 작업 완료 후 납품 요청 | 프리랜서 |
| 3. 납품 확인 | 의뢰인이 납품물 검토 후 완료 승인 | 의뢰인 |
| 4. 대금 지급 | 플랫폼이 프리랜서에게 수수료(10%) 차감 후 지급 처리 (실제 이체는 미구현) | 시스템 |

### 5.3 리뷰 시스템

#### 5.3.1 상호 평가

- 프로젝트 완료 상태에서만 리뷰 작성 가능
- **의뢰인 → 프리랜서 리뷰:** 별점(1-5), 텍스트 리뷰, 태그 선택 (책임감, 소통, 기술력 등)
- **프리랜서 → 의뢰인 리뷰:** 별점(1-5), 텍스트 리뷰, 태그 선택 (명확한 요구사항, 신속한 피드백 등)
- 리뷰는 1회만 작성 가능하며 수정 불가
- 사용자 프로필에 평균 별점 및 리뷰 목록 표시

> ✅ **스프린트 4 종료 기준:** AI 분석, 결제 흐름, 리뷰 작성까지의 전체 서비스 플로우가 배포 환경에서 동작해야 합니다.

## 9. 개발 협업 규칙

### 9.1 Git 브랜치 전략

| 브랜치 | 용도 | 명명 규칙 |
|--------|------|----------|
| `main` | 배포 가능한 안정 버전 | |
| `develop` | 개발 통합 브랜치 | |
| `feature/*` | 기능 개발 브랜치 | `feature/user-auth`, `feature/project-crud` |
| `fix/*` | 버그 수정 브랜치 | `fix/login-error` |

### 9.2 커밋 메시지 컨벤션

| 타입 | 사용 상황 | 예시 |
|------|----------|------|
| `feat` | 새로운 기능 추가 | `feat: 프리랜서 프로젝트 지원 기능 구현` |
| `fix` | 버그 수정 | `fix: 로그인 토큰 만료 처리 오류 수정` |
| `refactor` | 코드 리팩토링 | `refactor: 프로젝트 컨트롤러 분리` |
| `docs` | 문서 수정 | `docs: API 명세서 업데이트` |
| `style` | 코드 포맷팅 | `style: ESLint 규칙 적용` |
| `chore` | 빌드/설정 변경 | `chore: Prisma 마이그레이션 추가` |

### 9.3 코드 리뷰 규칙

- PR(Pull Request)은 `feature` 브랜치 → `develop` 브랜치로 생성
- PR 제목에 구현한 기능 명시: `[feat] 사용자 회원가입 API 구현`
- PR에 구현 내용, 테스트 방법, 스크린샷(UI 변경 시) 포함
- 팀 프로젝트의 경우 최소 1명의 팀원 리뷰 후 머지
